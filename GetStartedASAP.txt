Quickstart guide for the time-impaired

caitlinch/chromatin-assembly

GET STARTED BY FOLLOWING THESE STEPS:
1. Download the caitlinch/chromatin-assembly GitHub repository and move it to where you want to run your pipeline (e.g., /scratch3/che318/)
2. Navigate in terminal to the "chromatin-assembly" directory
3. Create conda environment using command: "conda create --name Step6_utils --file workflow/envs/Step6_utils.txt"
4. Open and export conda environment using: "conda activate Step6_utils; conda env export > workflow/envs/Step6_utils.yaml"
5. Within the chromatin-assembly directory, create a directory called "data". Create a new directory within "data", named after your species (e.g., "data/gecko/"). Inside the species folder, create three folders: "input_control", "reads", and "reference_genome". Copy your data into the relevant files. It should look like this (where "species" is replaced with your species name):
	- chromatin-assembly/data/species/reads/ – contains raw reads
	- chromatin-assembly/data/species/input_control/ – contains input control for DANPOS3 (peak analysis)
	- chromatin-assembly/data/species/reference_genome/ – contains reference genome in fasta file format
6. Open the file "config/chromatin_assembly_config.yml" and update file paths and parameters for your data
7. Update SLURM details in the job scripts using the command: "module load R; Rscript resources/user_update_jobscripts.R mail-user={email@email.com} mail-type={when_mail} account={account}"
	- Replace each set of curly brackets with your preferred SLURM details
	- For example: "module load R; Rscript resources/user_update_jobscripts.R mail-user=test@test.com mail-type=FAIL account=OD-123456"
	- See UPDATING SLURM JOBSCRIPTS below for more details
8. Update account ID in slurm profiles (chromatin-assembly/profiles/hpc_test/config.yaml, chromatin-assembly/profiles/slurm/config.yaml) with your own
9. (Optional) Perform a dry run of the full pipeline in the terminal (interactive mode) with command "snakemake -n -p -c1" or "sbatch jobscripts/pipeline_dry_run.sh"
10. (Optional) Merge reads with "sbatch jobscripts/slurm_pipeline_S0.sh"
11. Perform Step 1 (read masking) and Step 2 (QC) with command  "sbatch jobscripts/slurm_pipeline_S1-2.sh"
12. Perform Step 3 (UMI extraction) and Step 4 (kalign) with command  "sbatch jobscripts/slurm_pipeline_S3-4.sh"
13. Perform Step 5 (remove duplicates), Step 6a (two-bit genome) and Step 6b (calculate genome size) with command "sbatch jobscripts/slurm_pipeline_S5-6b.sh"
14. Update the effective genome size value in the file "config/chromatin_assembly_config.yml", Section 4: Intermediate output
15. Perform Step 6c (compute GC bias) and 6d (correct GC bias) with command "sbatch jobscripts/slurm_pipeline_S6c-6d.sh"
16. Perform Step 7a (calculate alignment statistics) and 7b (estimate mean nuclear genome covert) with command "sbatch jobscripts/slurm_pipeline_S7a-7b.sh"
17. (Optional) Perform Step 8 (peak analysis with DANPOS) with command "sbatch jobscripts/slurm_pipeline_S7a-7b.sh"



UPDATING SLURM JOBSCRIPTS
To update SLURM details in the jobscript, enter the following command into the terminal: 
	"module load R; Rscript resources/user_update_jobscripts.R mail-user={email@email.com} mail-type={when_mail} account={account}" 
Arguments:
{email@email.com} - your email e.g., mail-user=test@test.com
{when_mail} - your email preferences e.g., mail-type=END or mail-type=FAIL,END,TIME_LIMIT
{account} - account ID for SLURM accounting e.g., account=OD-123456

Putting this together, a sample command would be:
	"module load R; Rscript resources/user_update_jobscripts.R mail-user=test@test.com mail-type=FAIL,END,TIME_LIMIT account=OD-123456"

If you do not wish to receive any emails from SLURM, set mail-user=FALSE and mail-type=FALSE:
	"module load R; Rscript resources/user_update_jobscripts.R mail-user=FALSE mail-type=FALSE account=OD-123456"

All jobscripts will be copied with your updated user preferences into the jobscripts/ directory.

PIPELINE DEVELOPMENT AND TESTING:
This pipeline was developed to be run on:
- the Petrichor server (at CSIRO)
- Using Slurm (either by submitting jobscripts as listed above, or by using the command line as detailed in the documentation)
It has not been tested in other environments.



HAVING PROBLEMS? SOMETHING NOT WORKING?
Troubleshooting:
- Try running a dry run with the command "snakemake -n -p -c1" - sometimes you might be missing a file or have an incorrect file path

Potential issues:
- Snakemake not found? Check job script includes the line "module load python"
- Not enough resources supplied in job scripts? Update resources in SBATCH lines
- Not enough resources supplied to Snakemake? Update resources in "profiles/slurm/config.yaml" file
- Read file path naming convention: 
	- This pipeline was tested on reads with the structure: {sample_id}_{some_text}_L00{num}_R{1|2}.fastq.gz
	- For example, R114096_22W5TWLT3_TTCTGCGTCG-TTCGTACACC_L003_R1.fastq.gz
	- If you have data with a different file name structure, you may have issues running the pipeline.
	- Potential pitfall: your read filenames have an extra argument after the R1/R2 e.g., SampleName_S1_L001_R1_001.fastq.gz
- Merged read file path names:
	- This pipeline names merged reads with the structure: {sample_id}_merged_R{1|2}.fastq.gz
	- For example, R114096_merged_R1.fastq.gz
	- If you have merged reads with different naming structure, the pipeline will not work
	- Potential pitfall: your merged reads have the file path naming structure: {sample_id}_R{1|2}_merged.fastq.gz
